# 轨道旧货局手机横屏界面与操作动画保留方案

日期：2026 年 11 月 11 日。状态：设计草案，供审阅。横屏布局方向已确认；本轮交付文档，不实施横屏改造或发布线上。

核心要求：采用手机专用的横屏柜台与可展开工作台，完整保留现有操作动画、手动操作、过程反馈与进度。界面可以重排，操作过程不能被静态图、结果提示或一键完成取代。

## 一 需求与范围

已确定的要求是：手机横屏拥有更充分的可视和操作空间；主页面固定一屏，不需要滑动；详细内容按需打开，弹窗及工作页面有清楚的关闭按钮；现有操作动画全部保留。

本方案默认保留 PC 界面和已有竖屏作为兼容入口。横屏不使用整张 PC 画面的缩小或 CSS 旋转。切换方向不新开一局，不丢失当前顾客、物品、报价和已保存工序。机型不能强制全屏或锁定方向时，仍可正常操作。

本轮不改价格、真假、鉴定估价区间、材料、行动点、电费、NPC 交易和存档规则，也不删减维修、独立翻新、加工、仓储、订单及事件功能。

## 二 已选的布局方式

| 方式 | 操作特点 | 本方案选择 |
| --- | --- | --- |
| 缩小 PC 场景 | 保留原构图，但文字与命中区域仍偏小 | 不采用 |
| 所有功能分别全屏 | 单项空间充足，但看顾客、物品和报价需要频繁切换 | 不作为普通接客方式 |
| 横屏三栏柜台加可展开工作台 | 普通接客同时看到对话、实物和交易；精细操作扩大工作区 | 采用用户已确认的方向 |

普通接客时，左侧是顾客窗口与对话摘要，中央是当前实物与工具，右侧是开价和交易操作。顶部放营业日、现金、AP 与设置，底部放柜台、仓库、工作台、事务和说明书入口。

```text
┌────────────── 营业信息与设置 ──────────────┐
│ 顾客与对话 │ 实物工作区与工具 │ 报价与交割 │
│            │  可展开鉴定台   │            │
├───────────── 固定功能入口 ───────────────┤
└──────────────────────────────────────────┘
```

以有效视口 844×390 CSS px 为主要设计尺寸。扣除安全区与间距后，左右信息区让出空间给中央实物；展开工作台后，左右栏收起，仅保留必要状态、当前步骤、工具和关闭按钮。具体像素宽度由实际安全区决定，不以固定 PC 坐标硬套。

主页面和实际操作区域均不依赖页面滚动。长对话、物证记录、说明书、订单和库存清单可以在独立面板内部滚动，关闭按钮固定在内容滚动区域之外。

## 三 两种主状态及切换

### 普通柜台

同时保留顾客、实物、开价和主要交易动作。放大镜、紫外灯和电子秤直接可选，另有“展开鉴定台”入口。多件货物展示当前选中实物与件数，完整选货清单按需打开。

接客、放货、议价反馈、递钱、交接原物、打印回执与送客，在这张柜台中可见。交割涉及多件物品时逐件显示真实交接，不能只移动当前选中的图标。

### 展开工作台

点击鉴定工具或进入维修、翻新、加工时，中央变为主要操作空间。维修与加工使用完整工作台，不能塞进小型确认弹窗。

工作区同时容纳当前实物、正在使用的工具及当前步骤需要的零件盘。宽屏布局需要重排工具、零件盘和操作锚点，不能仅将旧的 640×460 操作画面整体缩小塞入横屏。手指正在拖动时，镜头和缩放不自行漂移。

右上角固定显示“关闭并返回柜台”。返回后仍是同一位顾客、同一件物品及原报价草稿；已保存的操作进度可继续。布局展开、收起和方向切换不能重新抽取故障、清零已保存进度或再次扣费。

## 四 动画保留的硬性约束

“保留”同时满足四件事：动作确实播放、玩家实际看得到、原有手动操作仍然有效、物品与结算状态保持一致。后台运行了动画、前台却只显示静态图，不算保留。

现有竖屏展示层使用过静态顾客头像和物品图标，并隐藏原场景节点。横屏不能照搬这种展示方式。顾客必须使用动态角色表现，柜台实物必须能实时呈现拖动、翻面、落台和已有特殊效果；工作台继续呈现真实工具、部件和步骤。

现有工作台的“取工具 → 接触 → 执行 → 撤离 → 结果”过程必须完整呈现。玩家需要拖拽、擦拭、定位、按住或装配的步骤，仍由对应操作驱动；已有自动完成的短动画按原规则播放。不能改成点一下直接跳到结果，也不能用循环视频冒充实际操作。

默认完整保留动画。现有“减少动态效果”选项继续尊重玩家主动选择，不因手机设备或性能偏低而自动启用。性能优化先处理无关粒子、背景光效及渲染成本，不能跳过工具接触、关键拆装、交接原物或操作判定。

## 五 必须保留的动画清单

以下清单是实施时逐项核验的最低范围。发现同一模块还有其他现有动画，应补入清单并保留，不能因未写入表格而删掉。

### 柜台与通用实物

| 类别 | 必须保留的表现 | 横屏呈现位置 |
| --- | --- | --- |
| 服务铃与来客 | 铃体按压和回摆；顾客走入、停稳、离开 | 左侧服务窗口及柜台前沿 |
| 顾客反馈 | 交谈、表情切换、点头、摇头及成交反应 | 动态顾客窗口 |
| 物品放台 | 实物从来客或货物区移动至桌面，抬起、落下与落稳反馈 | 中央柜台 |
| 实物操作 | 拖动、翻面时的抬起与转动、正反面切换、选中轮廓及现有珍稀款动态效果 | 柜台及展开工作台 |
| 钱货交割 | 钞票按收付方向移动、现金同步变化，实际约定的原物逐件交接 | 跨区域的柜台动效层 |
| 回执与送客 | 出票、盖章、撕单等现有回执过程；成交或拒绝后相应的取回货物和离开 | 交易区、实物区与顾客窗口 |
| 其他现有交互 | 仓储拖放与旋转、纸张移动与缩放，以及已存在的事件和界面过渡动画 | 对应页面或面板 |

### 鉴定

| 工具 | 必须保留的操作与动画 |
| --- | --- |
| 放大镜 | 镜片移动、局部放大、观察点定位或固定、停留观察进度及记录反馈 |
| 紫外灯 | 灯具与照射范围移动、紫外光效果、后盖编号显现、定位与观察记录过程 |
| 电子秤 | 空秤归零、实物移入秤盘、秤盘反馈、读数逐步稳定、稳定后按原规则记录与移出 |

翻面必须调用真实物品翻面过程，不能直接替换正反面静态贴图。鉴定只呈现当前工具能观察到的内容，不能因横屏增加隐藏真相或精确市价。

### 维修工单

| 工序 | 必须保留的操作与动画 |
| --- | --- |
| 清洁除尘 | 擦布跟随实际接触路径，污渍在擦过的位置逐渐减淡；残留、完成判定与画面一致 |
| 开盖拆检 | 按实际结构操作开盖器、刀具或螺丝刀；后盖、螺钉和检查工具在正确位置移动 |
| 零件清洗与干燥 | 取出可洗部件、移入清洗篮、清洗、沥干与吹干的完整过程 |
| 故障件修复与更换 | 松开固定、取出旧件、装入匹配新件、固定与复核；包括已有内部件及外部表节流程 |
| 定点润滑与回装 | 适用位置点油，零件按顺序落座、固定并恢复必要供能；石英和机械流程保持区别 |
| 走时校验与交工 | 当前机型对应的检测、调节、读数反馈与封盖；未完成前不提前显示全部修好 |

随机工单仍只要求本件实际需要的步骤。“全部保留”不意味着强迫每只表把所有工序重做一遍。

### 独立翻新

| 项目 | 必须保留的操作与动画 |
| --- | --- |
| 吹除浮灰 | 气嘴靠近、气流作用与浮灰变化 |
| 擦拭清洁 | 清洁工具接触并移动，表面污渍按现有规则变化 |
| 表壳抛光 | 抛光工具沿指定壳体区域移动及现有表面反馈 |
| 更换表壳 | 安全处理、开盖、取出原总成、旧壳入盘、新壳落座、原总成回装与封盖 |
| 更换表带 | 生耳等固定结构的释放、旧表带移出、新表带对位与固定 |

### 伪装加工

| 项目 | 必须保留的操作与动画 |
| --- | --- |
| 重描标识 | 描绘工具接触、标识逐步形成及已有加工反馈 |
| 紫外编号加工 | 对应清洁、覆印或描绘、紫外检查及编号显现过程 |
| 配重加工 | 开盖、配重移动与放置、固定、称量反馈以及封盖 |
| 改装目标外壳 | 原总成拆出、目标壳与相应表带装配、回装和对应后盖处理 |

加工后的外观、编号、重量及已有痕迹仍由原模型计算。动画换布局不改变真实型号、真假、隐藏故障或 NPC 识破规则。

## 六 关闭与中断规则

关闭按钮必须始终可见，不能藏在长内容底部，不能被工具、回执、提示条或浏览器安全区遮住。普通面板显示“关闭”，展开工作台显示“关闭并返回柜台”；关闭与放弃交易、取消约定、完成工序是不同动作。

| 当前状态 | 点击关闭后的行为 |
| --- | --- |
| 查看对话、详情、记录或说明书 | 关闭当前层，回到打开前的界面；不更换物品，不提交交易 |
| 议价输入中 | 关闭议价面板，保留当前报价草稿；不发送出价或接受动作 |
| 正在拖物、擦拭或移动镜片 | 先释放接触与指针捕获，保存本来支持持久化的实际进度，再关闭；不留下隐形拖拽 |
| 正在执行不可安全拆开的短动作段 | 立即显示“完成当前动作后关闭”，在当前短段到达稳定边界后关闭；不连续自动执行后续工序，不静默忽略关闭 |
| 操作完成但尚待确认结算 | 按现有工序保存完成状态，返回后仍可核对和提交；关闭不能冒充提交 |
| 钱货交割已经开始 | 保持交易过程可见，其他切页操作暂不可用；原物交接与结算反馈完成后再恢复操作，不取消或重复已经成立的成交 |

关闭本身不新增费用，也不回滚已经按原规则发生的耗材、电费或成交。没有完成的动作不能因退出自动成功。未持久化的临时观察计时退出后停止；已记录物证不丢失，未完成观察不自动生成物证。

多层界面每次只关闭最上层：例如说明书关闭后回到鉴定台，鉴定台关闭后回到柜台。浏览器返回和系统返回如能接管，应遵循同样层级；不能依赖它们替代可见关闭按钮。

## 七 动画与布局的实现边界

继续使用 Godot 的真实角色、实物、鉴定和工作台控制器。布局组件负责位置、大小、入口与信息展示，不另写一套维修或交易规则。

普通柜台和展开状态只能有一个操作权威：同一件物品、同一工序和同一笔交易不能有两份控制器同时收输入或推进。可采用现有节点重排或受控的共享渲染视图，具体选型交给实施，但必须保留实时动画和准确的输入映射。

跨区递物、钞票和回执使用能跨越分栏边界的动效层。起终点从当前顾客手部、桌面、货物区和收银区的实际锚点取得，不能沿用 1920×1080 桌面坐标；不能让分栏裁切把交接路径截断。

展开或旋转时，改变的是显示布局和坐标映射，不能重新创建物品来掩盖状态丢失。若当前正在接触或执行动作，先按上一节安全退出接触或到达稳定边界，再重排。维修和翻新的步骤、阶段、工具及部件位置、擦拭遮罩等，按现有存档能力恢复。

## 八 手机操作与尺寸约束

优先覆盖有效视口 844×390、932×430、740×360 和 667×375，并检查浏览器工具栏占用后的实际可视高度。横屏左右安全区不放必须点中的按钮。

常用点击区域至少 44×44 CSS px，正文优先 14–16 CSS px；不能靠整体缩小实现“全部放下”。空间不足时收起次要信息、展开工作台或打开面板，不压缩手指命中区域。

小零件可以放大命中区域，但相邻零件的热区不能互相覆盖。手指与工具接触位置可有可见偏移，真实命中仍按统一的坐标映射计算。拖拽、双指手势与页面关闭之间需要明确的指针释放规则，不能让第二根手指意外触发出价或关闭。

## 九 保存与性能

布局、方向和面板切换不更换物品 UID。现有已记录物证、维修故障、拆装状态、独立翻新进度、加工进度、选定货物与报价草稿继续跟随原物。

对现有支持持久化的工序，在稳定边界或既有保存时机保存；切后台时停止接受新操作，避免恢复时把后台经过的时间一次性算成观察或擦拭完成。对暂不持久化的临时视觉状态，恢复为安全待操作状态，不伪造已完成进度。

本方案对系统中断作如下默认设计：页面内主动关闭或切换布局，必须遵守第六节的动画和安全边界；仅切到后台且场景仍在内存中时，暂停并在恢复后继续当前过程。浏览器强制刷新、关闭或系统杀死进程后，未持久化的交易过场不承诺自动续播。

现有交易先保存实际账目，再通知界面播放递钞、交接和回执。因此，强制中断后的读档以已经保存的交易状态为准，显示明确的已成交状态，并提供查看既有账本的入口；不为了补播画面重新提交收付款或交接。“动画全部保留”在本方案中指正常可控流程无删减，不将强制销毁场景后的过场续播纳入本轮。若后续要求该能力，需要另行设计持久化的过场恢复记录；不能靠重放交易动作实现。

工具、角色和材质资源复用，避免每次打开面板重复解码图集或重建动画。布局刷新只更新必要信息，不反复重建正在执行的场景。性能不足优先降低装饰开销；不能把交互步骤变成静态结果来换取帧率。

## 十 验收标准

- 普通横屏柜台一屏显示顾客摘要、实物、开价、主要动作和导航；不需要滑动主页面。
- 工具和维修进入展开工作台后，操作目标、当前工具与相关零件完整可见，画面不会裁掉关键接触点。
- 第五节清单逐项验收。每类动画需记录实际触屏操作，包含开始、接触、进行和结束；只看静态截图不能判定动画保留。
- 与当前桌面版本对照，不能出现只换贴图的翻面、只跳数字的称重、隐藏的递物或递钞、点一下直接维修成功等回退。
- 覆盖简单外部维护、石英维修、机械保养、五类独立翻新和四类加工；按机型与工单挑选适用项目，不伪造不适用工序。
- 多件交易确认后，交接的是实际约定的每件原物；动画方向、收付金额与结果一致。
- 关闭、返回、切换货物、切换工具、旋转和读档后，已保存进度保留；不重复扣费、不重复加货、不残留拖拽或忙碌状态。
- 每种面板检查关闭按钮的位置、命中和返回层级；关闭议价不能提交，关闭说明书不能顺带退出整个工作台。
- 常见横屏尺寸、浏览器工具栏与安全区下均可完成操作；不支持锁屏或全屏的环境也能玩。
- 原生状态测试、真实触屏浏览器测试、进度保存测试和实际录屏同时提供。发现清单中的任一操作变成不可见或一键结果，该轮不通过。

## 十一 实施分段

先完成“顾客接客、实物放台与翻面、三种鉴定、钱货交割”这一条完整横屏样例，证明布局和动态场景能够共存；再接入维修、独立翻新、加工及其他页面；最后执行全部动画与旧存档回归。分段用于控制实施顺序，不表示后半部分可以删掉或提前宣称全量完成。

最终交付包括横屏实机版本、动画保留核验清单、关键操作录屏和回归结果。当前阶段仅审阅设计，实施及上线在后续任务进行。

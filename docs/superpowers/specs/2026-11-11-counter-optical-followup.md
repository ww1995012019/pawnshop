# 柜台与光学工具问题修复

本次在 78 款手表扩充工作中追加，功能扩充和已确认的概率规则继续保留，一起验证发布。

用户截图和报错明确了以下要求：

- 展开协查名单或检验说明书时，放大镜在窗口以外仍可顺畅操作；纸张继续保持可拖动、缩放和非模态。鼠标位于纸张或对话框上时，不操作或展示下层内容。
- 放大镜内保留表盘颜色和标识，不把浅色表盘放大成纯白；保持实物检验、标识遮挡、翻面与固定观察行为，不额外泄露真伪。
- 对话框中的正文不再产生重复的长条悬浮提示。
- 明确表示本趟不收、数量或预算已满、识破拒收以及真正结束的交流，在文字可读后约 3 秒自动送客。新交易动作可取消旧计时；未交割的已谈妥商品不能被自动结束。原物、NPC 留存商品、账本和 AP 不丢失、不重复处理。
- 警察进场和带走人时，不显示遮住警察的大块结果对话框；结果通过不遮挡人物的简短状态提供。
- 修复举报后完整动画路径的 `Uncaught RuntimeError: null function`，确保抓人完成后解除忙碌状态，还能继续接待。核对误报、正常和减少动态模式、多件原物与后续来客。

已复现的根因证据：完整动画下，警察动画释放了柜台实物节点，却没有先从 `counter_table.sprites` 中移除；其后处理继续访问已释放的 `sprite.body`。真实 WebGL 复现了相同 `null function` 和 `busy=true` 卡死。修复应维护节点与柜台索引的一致性，不能仅捕获网页异常或重载。

光学待验证假设：浮动纸张每帧重新布局角落，调用同步 JavaScript DPI 查询；镜片采样的是已经受光的屏幕，但着色器仍参与灯光，可能造成重复增亮。须通过性能计数与真实渲染对比确认后修复。

原有新表维修台非圆外形的刻度、高光和盖板装饰也需跟随轮廓，避免椭圆壳外出现圆形装饰；操作点与所见部件对齐。

# 抢劫与报复实施计划

按已确认设计执行，先写回归测试再实现。

1. 新增独立抢劫模型：每日持货概率、5%资产目标的1～3件选品、持久案件。
2. 接入原物案件追踪、销赃和报警抓捕；本店抢劫标记无需编号证据。
3. 普通抓捕单次5%报复，2～7天后执行；站务关系60且现场5%抓捕豁免。
4. 维修费按当时资产5%～8%整数档向上取整；歇业全天，可负余额，次日恢复。
5. 标记、事件簿、报警文案和歇业账单；补充概率、读档、原物与UI测试。
6. 跑完整项目测试、打包检查与浏览器回归，记录结果后更新部署。

实现约定：第3天起开门前每日一次；旧档当前营业日不补抽；与旧夜间失窃独立，不自动理赔。总资产=max(0,现金+所有自有手表估值)。风险统计自有手表；仅合法、未占用、未封存且在后仓/展示的原表可被抢。选取价值最接近资产5%的1～3件，差值相同优先更少件。复用旧销赃日程（案发至少2天后，每日有空闲来客槽时20%抽取本店失物回流）。抓捕追回仍由该犯持有的全部本案原物，满仓进入待领区。

报复日不接客、不加工；正常固定费用及到期租金自动记账，允许欠款，跳过破产检查，避免负余额锁死。现有订单、委修和保管事件的未结束期限顺延一天，拍卖随日历照常。费用只结算维修费，不额外损坏库存。隐藏的报复判定不在玩家事件预告中泄露。

## 验证结果

- `npm test` 完整通过，原生回归104/104组；字体、资源、打包与加载布局检查通过。
- 最后补充的原物转案标记与竖屏提示用例单独重跑通过；`portrait_counter_test` 兼容回归通过。
- `scripts/test-robbery-web.py` 在1440×900、568×320、390×844均通过真实点击报警、同UID追回、歇业负余额进入次日与刷新防重复扣费。
- 发布包资源检查：78种物品、33位居民、3种仪器，0失败。
- 2000个确定性种子中的普通抓捕报复命中107次；同次多案抓捕最多一宗报复，现场抓捕均无报复。
- 覆盖满仓待领、原物不复制、旧案件转案后标记、抓获熟客不返场、委修与返修窗口顺延。
- 代码审查发现的多次报复抽样和期限边界问题已修复，并追加回归。
